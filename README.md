# 果トレ

中小企業診断士2次試験のMMCメソッドに基づき、本試験の設問文とMMC解説に明記された題意から「切り口」と「果キーワード」を想起する個人学習PWAです。問題・履歴・設定はすべて端末内に保存され、インターネット接続がない環境でも利用できます。

## 主な機能

- 2023〜2025年度、事例I〜IVの51回答単位を収録
- 本試験の設問文全文と、MMC解説に明記された題意を出題時に表示
- 字数制約を強調し、複数のMMC題意をタグで表示
- SWOT・小問・計算／記述の組合せは、採点単位ごとに「今回の回答対象」を明示して1問ずつ出題
- 年度・事例・未回答・要復習・出題数による絞り込み
- タグ形式の切り口／果キーワード入力
- 表記正規化・部分一致・同義語辞書を使った100点満点の採点
- 4段階の自己評価と復習指定
- 学習履歴、端末内保存、JSONバックアップ／復元
- 制限時間、同義語判定、ダークモード
- PWA、オフライン対応、スマートフォン優先UI
- 年度・事例別の一覧モード（設問文・MMC題意・果キーワードの対応を出題順に表示）
- 一覧では果キーワードを設問ごとに開閉でき、確認後にMMC模範解答を二段階目として表示
- 過去3年分の果キーワード辞典（同じ果を使う設問を横断表示）
- 全事例／事例別の果キーワード頻出ランキング
- 個人用OCR教材JSONの端末内インポート（公開データとは分離）
- 「本試一問一答」「題意トレ」「棚から果トレ」「因→果」「目的→施策」の5モード切替
- 題意トレは「題意・与件のトリガー → 題意の棚」、棚から果トレは「題意の棚 → 果キーワード」を反復
- MMC 2026強化答練6事例（Cs411・Cs412・Cs421・Cs422・Cs431・Cs432）のsource付きトリガー辞書
- 題意・トリガー一覧で、トリガー／棚／果／出典を横断検索
- 回答後に正誤・苦戦理由・弱点タグを記録し、優先度順に弱点復習
- 「因→果」「目的→施策」モードと事例Ⅰ・Ⅲの重点プリセット
- 本試一問一答では企業概要と題意を見て切り口を先に答え、次に設問文を読んで果キーワードを答える二段階演習
- 事例・タグ別正答率、果キーワード不足／題意判断の別集計

## 弱点復習

ホームの「弱点復習」「事例Ⅰ重点」「事例Ⅲ重点」から始めます。条件画面で年度・事例・弱点タグ・前回不正解・前回時間がかかった・過去N回の低正答率・最近の間違い・未復習期間を組み合わせて絞り込めます。タグの選択肢同士はOR、異なる条件の間はANDです。未復習期間は30日、最近の間違いは14日、時間がかかった目安は180秒です。優先度の重みは `src/features/weakness/weaknessReview.ts` の `priorityWeights` で調整できます。

回答後には自動採点とは別に正誤を指定し、「果キーワードが出なかった」「思い出すのに時間がかかった」「題意の切り分けに迷った」を複数記録できます。タグは事例別の候補から選択するか自由に追加できます。記録したタグと履歴は端末内に保存され、バックアップJSONにも含まれます。旧バックアップも読み込めます。

「因→果」「目的→施策」は、今回提示された演習メモの具体例を `public/data/kahotore_weakness_practice_v1.json` に収録しています。候補のうち一つでも一致すれば自動採点上は正解です。表記揺れ・部分一致・登録済みの同義語を許容し、自動判定と異なる妥当解は回答後の正誤指定で補えます。演習メモはMMC原資料由来のレコードと出典を区別しています。

## 題意トレ・棚から果トレ

「本試一問一答」は年度・事例に固有の問題を扱います。最初に業種・事業概要と題意（必要に応じてフレームワーク）を表示し、切り口を入力した後に設問文と果キーワードの入力欄を表示します。「因→果」「目的→施策」は過去問の暗記を前提にしない汎用演習で、別の問題データと画面を使用します。

本試一問一答の果は、最初の振り分け段階では一般的な候補で構いません。具体的な模範解答語と同じ方向の一般語は `src/data/generalFruitKeywords.ts` の明示的な対応で正解に含めます。1つの一般語で複数の果を埋めず、強みと不足など逆方向の回答も一致にしません。設定で「同義語・一般化判定」をオフにするとこの対応は使いません。事例Ⅳの数値・計算答案には一般化候補を設定していません。

ホームの「題意トレ」「棚から果トレ」、または演習条件画面の「トレーニング」から切り替えます。既存の本試一問一答は「本試一問一答」としてそのまま利用できます。

- **題意トレ**: 「交流」「部品削減」「見込生産」などのトリガーから、開くべき題意の棚を答えます。
- **棚から果トレ**: 「サービス」「設計」「生産管理」などの棚から、使える果キーワードを答えます。
- 年度・事例・学習状況・出題数の絞り込みは5モードで共通です。
- 入力の正規化と同義語判定は、既存の採点処理を流用しています。

題意の棚は次の事例別構成です。

- 事例I: SWOT・強み／経営戦略／組織構造／人的資源管理／新事業・事業展開
- 事例II: SWOT・3C／ターゲット／情報発信／製品・品揃え／サービス／プロモーション／関係性マーケティング／協業
- 事例III: 強み／設計／生産管理／品質管理／情報管理／営業／技能承継／外注

題意・トリガー一覧は、ホームの「題意・果の辞典」または本試設問一覧上部のリンクから開きます。「本試3年／強化答練」、事例、検索語で絞り込み、トリガー・棚・果・出典を一画面で確認できます。

強化答練データの正本は `public/data/kahotore_trigger_dictionary_v1.json` です。各レコードは `source` と `source_type` を持ち、解答・解説で確認できた内容だけを収録しています。一般知識による補完は行っていません。既存の本試3年データは、`question_summary`、`answer_unit_label`、`mmc_theme`、`cuts`、`fruit_keywords` から題意検索用レコードを生成します。

## 一覧モード

下部メニューの「一覧」から開きます。年度と事例を選ぶと、回答単位へ分割された全設問が本試験の順序で並びます。前回選んだ年度・事例は同じ端末に保存されます。

果キーワードは初期状態ではすべて非表示です。「果キーワード」をタップすると、その設問だけを表示できます。さらに「MMC模範解答を見る」をタップすると、果キーワードをどのような文章で使うか確認できます。果キーワードを閉じると模範解答も閉じます。

「すべて表示」は果キーワードだけを一括表示し、模範解答は表示しません。「すべて隠す」または年度・事例の変更で、すべて初期状態に戻ります。一覧での開閉は採点・学習履歴・復習状態には影響しません。

一覧の最下部にも年度・事例の切替を用意しています。年度を変えても事例は維持され、事例を変えても年度は維持されます。通常の「次へ」は、同じ事例を新しい年度から古い年度へ確認し、最古年度まで進んだら次の事例の最新年度へ移動します。年度・事例の移動後は一覧先頭へ戻り、果キーワードと模範解答はすべて閉じた状態になります。

## 果キーワード辞典・頻出ランキング

ホームの「果キーワード辞典」、または一覧画面上部のリンクから開きます。

- **辞典**: 果キーワードを検索し、使われた年度・事例・設問を確認できます。
- **頻出ランキング**: 全事例または事例別に、同一設問内の重複を除いた出現回数順で表示します。

辞典・ランキングは `public/data/kahotore_mmc_base_v2.json` の `fruit_keywords` から画面表示時に生成します。辞典用データを別に保持しないため、問題データを更新すれば自動で反映されます。

表記ゆれを統合する必要が生じた場合だけ、`src/data/fruitKeywordAliases.ts` に「別表記: 正規表記」を追加します。意味が近いだけの語は統合せず、採点用の同義語辞書とは分けて管理します。

## 個人用MMC教材の読み込み

設定画面の「個人用MMC教材」から、専用JSONを読み込めます。教材はブラウザのIndexedDBだけに保存され、公開用の問題JSONやGitHubリポジトリには含まれません。同じ端末で新しい専用JSONを読み込むと、それまでの個人用教材を置き換えます。

OCR抽出直後のレコードは、一覧モードと果キーワード辞典で「個人用OCR未確認」と表示します。誤認識を正解として採点しないため、`answer_status` が `unverified` の個人用レコードはランダム演習と条件指定演習から除外します。内容を原本と照合し、`verified` に変更したレコードだけが演習対象になります。

個人用教材を消す場合は、設定画面の「個人用教材を削除」を使います。標準問題と学習履歴は残ります。教材PDF・専用JSONは個人学習の範囲で管理し、公開・再配布しないでください。

## セットアップ

Node.js 22.13以降を用意し、プロジェクト直下で次を実行します。

```bash
npm install
npm run dev
```

表示されたURLをブラウザで開きます。スマートフォンではブラウザの「ホーム画面に追加」からアプリのように起動できます。

## 確認とビルド

```bash
npm run test
npm run lint
npm run build
```

成果物は `dist/` に生成されます。ローカルで本番版を確認する場合は `npm run preview` を使います。

## GitHub Pagesへの公開

1. GitHub Desktopで変更内容を確認し、コミットして **Push origin** を実行します。
2. リポジトリの **Settings → Pages** を開き、Sourceを **GitHub Actions** にします。
3. **Actions** の「Deploy 果トレ to GitHub Pages」が緑のチェックになるまで待ちます。
4. `https://kds-yukimatz.github.io/mmc/` を開きます。以前の画面が残る場合は、ブラウザを再読み込みするか、ホーム画面のPWAを一度終了して開き直します。

公開処理は同梱の `.github/workflows/deploy.yml` が行います。Node.js 22とpnpm 11で依存関係を復元し、テスト済みの本番ビルドをGitHub Pagesへ配置します。

`vite.config.ts` は相対パスでビルドする設定のため、リポジトリ名にかかわらず配信できます。履歴は各端末のIndexedDBに保存されるため、公開しても他人と共有されません。

## 問題データの更新

アプリが読む正本は `public/data/kahotore_mmc_base_v2.json` です。更新時は同じ構造のJSONを作成し、`metadata.version` を上げます。アプリは起動時に問題データを更新し、`trainingResults` と `settings` は保持します。PWAは問題JSONをネットワーク優先で確認し、オフライン時は前回のキャッシュを利用します。

題意トリガー辞書は `public/data/kahotore_trigger_dictionary_v1.json` です。強化答練の追加時は、`trigger`、`shelf`、`fruit_keywords`、`source`、`source_type` を原資料と照合して追加し、辞書の `metadata.version` を更新してください。

今回追加した主要項目は次のとおりです。

- `question_text`: 本試験問題PDFの設問文全文
- `business_context`: 答えを含めない簡潔な業種・事業概要
- `framework`: 3C、SWOTなどの思考枠組み。ない場合は省略
- `cuts`: 答案を構成する切り口。SWOTの分割設問では回答対象の要素のみを保持
- `group_id`: 同じ大問に属する回答単位をまとめるID
- `sub_question_no`: 設問1、設問2などの小問番号
- `answer_unit_label`: 画面に表示する今回の回答対象
- `mmc_theme`: MMC解説に明記された題意の配列
- `theme_status`: MMC題意の確認状態
- `theme_source_pages`: MMC解説の参照ページ
- `question_status`: 設問文の確認状態
- `question_source_pages`: 本試験問題の参照ページ
- `answer_status`: MMC模範解答の確認状態
- `answer_source_pages`: MMC模範解答の参照ページ

JSONではsnake_case、アプリ内部ではcamelCaseへ変換します。問題データ更新後は `npm run test` と `npm run build` を実行し、51件の件数と分割設問の対応を確認してください。新たに1対多へ分割する場合は `public/data/migration_map.json` も更新します。

## 学習履歴のバックアップ

設定画面の「履歴をエクスポート」でJSONを保存します。復元先の端末で「履歴をインポート」を選ぶと、既存履歴を残したままID単位で統合します。旧IDが1対1で対応する場合は新IDへ引き継ぎ、1対多への分割では、誤った複製を避けるため親`group_id`の「旧記録」として保存します。ブラウザのサイトデータを削除する前や端末変更前にエクスポートしてください。

## 設計

- `domain/`: 問題、回答履歴、採点結果の型
- `repositories/`: 問題取得・履歴永続化の境界
- `services/`: 正規化、同義語、採点
- `features/training/`: 演習セッションの状態
- `features/question-list/`: 年度・事例別一覧
- `features/keyword-dictionary/`: 果キーワード辞典・頻出ランキングの生成と表示
- `db/`: Dexie / IndexedDB

採点は `GradingService`、問題取得と履歴保存はRepositoryインターフェースを介します。AI意味採点やクラウド同期へ移行するときは、画面を大きく変えず実装を差し替えられます。

## 現在の採点

- 果キーワード: 60点（登録語に対する一致割合）
- 切り口: 25点（登録語に対する一致割合）
- 効果語: 15点（対象語1種類につき5点、上限15点）

入力はNFKC正規化、空白・記号除去、小文字化を行い、部分一致と同義語辞書を適用します。

## データについて

設問文は2023〜2025年度の中小企業診断士第2次試験問題PDFと正誤表を参照し、設問番号・条件・字数制約を目視確認しています。`mmc_theme` は提供された「MMC本試3年解答帖（組織・流通・生産・財務）」の記載を使用し、推測や言い換えはしていません。`question_summary` は従来どおり題意要約として残しています。

全件の監査内容は `outputs/audit_report.md`、分割・移行方針は `outputs/split_records.md` と `outputs/migration_map.json`、未確認項目は `outputs/unverified_records.md` に記録しています。
